# 网关签名授权与 RJGT102 绑定

## 安全边界

生产网关采用三层校验：

1. 管理平台使用 Ed25519 私钥签发授权文件；私钥只保存在管理平台。
2. 网关程序只内置 Ed25519 公钥，启动和导入时验证授权文件全部字段。
3. 网关调用 RJGT102 完成设备认证并读取 USID，授权文件同时绑定 CPU 硬件指纹和芯片 USID。

授权无效、过期、被修改、复制到其他硬件或芯片认证失败时，网关进入受限维护模式。该模式仅启动本地管理页面和健康检查，不启动采集、转发、云连接、远程访问、边缘计算和告警任务。

## 授权文件内容

签名范围包含：授权版本、HardwareId、RJGT102 USID、SN、设备专用云凭证、MQTT 地址、云 API 地址、远程访问地址、签发时间、到期时间、功能列表和随机数。任何字段被修改都会导致验签失败。

## 首次部署顺序

1. 在离线管理电脑运行 `node tools/generate-activation-keys.mjs` 生成一对 Ed25519 密钥。
2. 将私钥环境文件安全导入云平台部署环境；不要复制到网关、交付包或源码仓库。
3. 将公钥环境文件提供给 EG100 生产构建流程。
4. 执行 Prisma 数据库迁移，增加 `FactoryGateway.chipUsid`。
5. 在网关运行状态页读取 HardwareId 和 RJGT102 USID，在管理平台登记实体网关。
6. 未激活网关无需登录即可查看待激活页、复制设备身份。点击“导入授权文件”后先登录验证管理员身份，再导入管理平台签发的文件；已激活设备可在云连接维护入口导入换发授权。
7. 网关验签并校验芯片成功后自动重启，随后才启动业务服务。

## 生产构建

未激活状态仅公开首页、静态资源和精简授权身份接口；业务接口不公开，授权预检和安装仍要求有效登录会话及 `cloud.manage` 权限，密码变更/MFA 要求不绕过。已激活后首页和授权状态接口恢复正常登录保护。匿名提示不包含内部授权路径或详细验证错误。

生产构建必须提供 `WK_ACTIVATION_PUBLIC_KEY`。构建脚本会同时启用：

- 硬件指纹强制绑定；
- Ed25519 签名强制校验；
- RJGT102 强制认证与 USID 绑定；
- 未授权受限维护模式。

禁止使用临时公钥生成可交付固件。

## 密钥和恢复要求

- 私钥应放入服务器 Secret 管理，不写入未加密的交付备份、日志、数据库或前端；当前本机部署使用访问权限受限的环境文件，导出的恢复备份必须加密。
- 私钥至少做两份离线加密备份，并记录密钥版本。
- 设备凭证必须每台设备独立，不能使用平台管理员密码。
- 更换签名私钥前需发布同时信任新旧公钥的过渡固件，避免已交付设备无法续签。
- 后续固件升级包也应使用独立的发布签名密钥，并增加版本防回滚。

## 当前兼容说明

源码开发构建默认不强制签名和芯片，便于单元测试。只有生产构建脚本注入强制开关和公钥后才进入严格模式。旧设备必须先补录 RJGT102 USID并换发签名授权，不能直接覆盖为严格固件。

## 第二阶段：密钥轮换与安全恢复

- 新签发文件使用 `licenseVersion: 2`，签名包含 `keyId` 和 `licenseSequence`。管理平台数据库对每台设备递增序号，签发失败不改数据库；并发签发通过序号条件更新拒绝冲突。
- 管理平台必须设置 `ACTIVATION_SIGNING_KEY_ID`、Ed25519 私钥和独立的 `FACTORY_CREDENTIAL_ENCRYPTION_KEY`。设备云凭据以 AES-256-GCM 加密保存，以便重新签发时保留连接；加密密钥必须独立备份，不能跟随签名密钥轮换。
- 构建时设置 `WK_ACTIVATION_TRUSTED_PUBLIC_KEYS` 为 JSON 公钥环（keyId → base64 公钥）；旧版单公钥仅用于 v1 兼容。先下发同时信任新旧公钥的固件，再切换管理平台签名 keyId。撤下旧公钥前必须完成旧设备换证，否则旧授权会进入维护模式。
- 网关在配置目录保存 `.license-state.json`，记录已接受的最大序号及签名载荷摘要。旧序号、同序号不同文件、不同设备身份都会被拒绝；同一文件重复导入允许。首次接受 v2 后拒绝 v1。损坏的记录不会自动清空。
- 授权导入先 POST 预检并显示摘要，再 PUT 安装。签名授权保存为版本化文件，原授权不截断；配置原子切换，加载失败恢复原配置。未应用文件可保留用于排查，但不会成为生效授权。
- 旧设备在出厂管理的“补录授权身份 / 凭据”中核对 HardwareId、补录芯片 USID；填写原文件中的 deviceSecret 时，平台先与现有散列比对，再加密保存。已登记的芯片身份不能随意更换，不能通过重发授权重置在用设备密钥。
- 云连接使用独立 `cloudConnectionEnabled`；关闭微控云连接不会关闭授权和本地业务。旧配置中的 activation.enabled 会迁移为云开关，签名 enabled 以授权文件为准。

软件高水位记录无法抵御 root 删除记录、整盘回滚或修改网关二进制。完整防复制仍需后续安全启动、独立固件签名及可信单调计数器；本阶段不宣称能抵御拥有 root 的攻击者。时间防回拨、在线吊销、SSH 稳定性也不在本阶段实现范围。

本阶段迁移脚本新增授权序号和加密凭据列；部署前需备份数据库，执行迁移，并完成真实 RJGT102 身份读取和首次授权联调。不得将测试密钥用于 EG100 生产构建。
