# 性能与商业化基线
版本：1.0.0

## 性能：已确认与待确认
已确认 U：S-02 用户描述生产服务器 2 核 2GB。
已确认 H：S-18 曾记录依赖未就绪导致 ingest 在线但无订阅的故障及恢复验证。
待确认：当前服务器、进程/容器分布、CPU/内存、存储、网络、生产负载、SLO、备份恢复时间。没有证据支持“可带 N 台设备”或“支持 N 万点”的承诺。此前 AI 方案的服务器规格是估算，不能进入已验收容量表。

建议采集的最小性能基线（草案）：
| 层 | 必测维度 | 结果/目标 |
|---|---|---|
| 网关 | 型号、CPU/内存、串口数、协议比例、设备/点位、采集周期、P95 周期超时、缓存增长 | TBD |
| MQTT | 在线连接、消息/秒、payload 字节、QoS、重连峰值、丢失/重复、订阅恢复 | TBD |
| ingest/时序库 | 点/秒、写入延迟、基数、乱序、积压、查询跨度、磁盘增长 | TBD |
| API/前端 | 并发、接口 P95/P99、错误率、图表点数、首屏及实时刷新 | TBD |
| 可靠性 | 连续运行时长、网络中断、数据库重启、磁盘满、恢复时间/恢复点 | TBD |

每次压测固定提交/镜像、配置、数据集、环境和时钟；区分冷启动/稳态/峰值。结果同时列 P50/P95/P99、失败分母及资源曲线，阈值由负责人依据业务确定。不要对生产或真实设备开展未授权压力测试。
可用估算公式：消息/秒 = 上报设备数 ÷ 上报间隔秒；采样点/秒 = 各设备点数 ÷ 各自采样间隔的求和。只有每次都全量上报时两者才能按固定点数换算；网关批量、变更上报、压缩、索引和副本会改变开销。原始流量不等于实际磁盘成本。

## 商业化：已确认
S-04 用户明确选择“买网关送一定额度，额度可以配置”；认可并非全免费、购买更多总体可更便宜。未确认具体优惠算法或固定阶梯。
S-07 当前 schema 有 SubscriptionPlan、TenantSubscription、SubscriptionOrder、PaymentProof、FinanceReview、QuotaAddon、EntitlementChange 等。它们证明已有数据结构，不证明支付、退款、赠额、转移都已实现。
S-19 产品型号规格管理不自动改变运行授权或网关配置。必须区分：
1. 硬件接口/采集能力；
2. 网关许可证允许的功能/点位；
3. 云端套餐及赠送权益；
4. 实际测得的云端处理能力。
四者不能互相替代。

## 待确认：禁止把示例价格写成正式套餐
早期聊天中的套餐名、年费、点数、存储期限、50% 折扣和每型号赠额均为建议，未列入正式价格配置。
建议权益拆分为“套餐基础 + 有效网关赠额 + 扩容 + 审批调整”，但该计算方式及各权益来源优先级尚需产品确认及源码核验。
需要确定：点位定义（创建/启用/上云）、上下线是否影响额度、赠额比例和上限、有效期、第三方设备、网关转移/解绑、退款回收、过期宽限、存量客户兼容、补差价和人工调整审计。

拟议验收场景：重复激活不重复赠额；网关转移不双计；退款与赠额回收幂等；并发订单无超发；套餐降级不静默删历史；失联不擅自收回永久权益；所有行为以最终批准规则为准。这些是测试建议，不是已选商业规则。

成本证据至少包含时序存储实际增长、消息/网络、备份、服务器摊销、售后与故障成本。数据库栈 Q-01 未解决前，不能将 InfluxDB 的单位成本套到本地 TimescaleDB 实测结果上。
