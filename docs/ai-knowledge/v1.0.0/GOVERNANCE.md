# 版本与知识治理
版本：1.0.0

## 三态与证据层级
status 只使用 confirmed / pending / deprecated，对应已确认/待确认/已废弃。
confirmed 必须限定 scope 和 evidence_level：user_statement、local_file、historical_report；本次没有 runtime_verified 类型的结果。
pending 含未决冲突和新增建议，可有候选答案，不能作为执行依据。
deprecated 保留原结论与替代项，不删除追溯；必须限定失效范围。

证据不是单一覆盖优先级：用户确认决定产品意图，源码说明局部实现，运行验证说明指定环境现状。冲突时同时保留，新增问题/ADR，不悄悄用一个覆盖另一个。旧测试报告只对原测试对象与时段负责。

## 版本规则
版本目录不在导入后就视为正式批准。初次导入先审阅；后续已合并版本保留快照，新增 v1.0.1、v1.1.0 或 v2.0.0 并更新 VERSION 和 README。
- PATCH：证据、措辞与非行为性纠错。
- MINOR：新增模块、补完待确认项，且不改变既定核心约束。
- MAJOR：技术主线、权限/商业规则等不兼容变化，附 ADR 与迁移影响。
文件头、VERSION、JSON knowledge_version 和 CHANGELOG 保持一致。文件哈希清单在内容最终固定后再生成；SHA256SUMS 不自包含。

## 修改审阅
知识变更 PR 至少列：旧结论、新结论、来源、适用范围、冲突处置、受影响任务。技术负责人审技术事实，产品/财务审商业规则，安全/发布负责人审授权边界。AI 不能自我批准政策升级。
主分支保护、CODEOWNERS、必需检查等仅在明确仓库后配置，本包没有部署这些机制。

## 建议 ADR 模板
ID / 标题 / 状态（proposed、accepted、superseded）/ 日期 / 决策者；
背景与冲突证据；选项；决策和适用环境；兼容与迁移；验证与回滚；替代关系。
Q-01 可形成首个数据栈 ADR，但当前应为 proposed，不能填入虚构审批人。

## 更新触发
合并影响行为的 PR、数据栈变更、协议实机验收、固件发布、授权策略变化、套餐批准或历史证据被推翻时更新。不要自动把“代码合并”转换成“已部署”。
不把完整源码、真实数据、账号、私钥和设备秘密打包到知识库；只保存最小必要描述和可追溯引用。本包源指纹仅覆盖选定文件，不是完整仓库归档。
