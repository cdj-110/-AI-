# Go 网关与工业协议基线
版本：1.0.0

## 已确认的结构
S-09：Go 网关目录 apps/gateway-go，go.mod 声明 go 1.25.7；该声明不是本机或设备运行时版本证明。webui 为独立前端，配置与 MQTT 主题见 README。离线缓存文档要求可移动存储，默认关闭、12–16MB 上限、满时淘汰最旧数据；这些是文档记录，当前全路径实现未复核。
S-10：Python 并行网关复用 Go 前端，文档端口 8089，与 Go 的 8088 分开；尚未迁移清单包括 IEC104、S7、IEC61850、CEL 完整语义及离线队列等。不能将它标为废弃，也不能以 Python 已有功能替代 Go 验收。
S-19：EG100 产品库后续修正规格见主基线。量产批次、CPU/内存/存储及 CAN 支持仍需 BOM 和实机数据。

## 两个不能丢失的技术边界
S-12 的 MMS 构建说明要求 EG100 ARMv7 使用 opcda,iec61850_mms 两个标签及 CGO，并保留 OPC DA 链接依赖。普通 go build 成功不能证明交付包具有这些协议能力。
T02 报告记录 INT64/UINT64 保留精确值，Web 通过 valueText 防止超过 2^53 的精度损失；SAFEARRAY 仅明确 R8/BSTR，其他类型不得误报 GOOD。报告中的固定边界、BOOL/DATE/UINT/ARRAY 尚未完成 Server→EG100 全链路实机覆盖。

## 建议的协议交付契约（待采用）
每个驱动提交能力清单：协议/版本、OS/CPU、构建标签、原生库版本、设备型号、读写操作、数据类型、质量码、时间戳、重连及错误映射。默认使用模拟器和合成数据。
验收至少区分四层：单元测试、模拟服务器、授权测试设备、生产灰度；四层结果不能互相替代。真实点位写入、遥控、重启、网络配置与 OTA 必须有针对目标的人工授权。
配置变更需要兼容策略、备份和回滚；采集失败不能继续把旧值标成 GOOD；写入受理不等于设备执行成功。上述是新角色规范建议，不宣称当前全部实现。
