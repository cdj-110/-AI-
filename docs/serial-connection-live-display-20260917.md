# 串口连接测试、协议说明和实时值显示修复

## 原因与调整

1. Modbus RTU 连接测试没有专用分支，HTTP 和 WebSocket 入口都落到通用 TCP 探测，所以 `/dev/ttyS1` 报 `missing port in address`。这不是截图能证明的接线或从站故障。
2. 补充 Modbus RTU 只读测试，使用资源串口参数、设备从站 ID 和首个读取点位的功能码/地址。每次只读一个寄存器或位，未配置点位时默认读取功能码 3、地址 0；设备不支持该地址时仍会明确报错，不把“打开串口”当通信成功。
3. 测试复用实际采集的 RTU 总线连接与互斥锁，等待总线时支持取消。拒绝广播从站 ID、写功能码和无效输入。不写寄存器、不保存设备配置。
4. 串口超时不再误提示 TCP 网络错误。保留真实底层错误，提示检查接线、从站 ID、串口参数和点位地址。
5. 协议说明从表单额外文字行移动到协议标题旁的提示图标，标题行/输入框与相邻字段保持对齐。说明改称“串口总线”，不限定 RS485。
6. 倍率运算可能产生 `43.300000000000004`。通用表格、手机卡片、其他协议表格及大点位工作区统一使用显示格式化；自动精度消除浮点尾差，显式小数位仍遵循配置。不改原始数据、倍率、上传值或字符串/大整数精确文本。

## 验证

- 网关前端构建与类型检查通过。
- Go collector / web 测试通过：共享总线读取、从站 ID、地址/单次读取数量、总线忙取消、串口超时文本、写功能码禁止、HTTP/WebSocket 不落到 TCP。
- 数值格式化测试覆盖 `433*0.1`、`0.1+0.2`、显式/自动精度、大整数精确文本、字符串、数组、空值和异常精度。
- 独立 Chrome 模拟页面检查第一行表单对齐、说明不占行、实时更新每一帧的文本、列宽保持稳定和手机布局。
- 实时值动画、删除设备导航、授权弹窗和激活/替换流程回归通过。
