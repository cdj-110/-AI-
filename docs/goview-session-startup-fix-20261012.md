# GoView 登录恢复启动修复

候选变更：修复登录恢复弹框提前加载引起的编辑器启动失败。本次在现有工作树保留此前变更，没有创建正式提交。

原因：App 同步引入 SessionRecovery；该组件引入编辑器 Store，而 Store 在模块顶层调用其他 Store，此时 main 尚未执行 setupStore。入口初始化被阻断，登录桥接参数没有清理，启动动画持续显示。此前仅 HTTP 200 与构建检查无法证明编辑器可启动。

修复：弹框改为应用挂载后异步加载；修正 immediate 监听位置；首轮会话续期放到应用挂载后，401 直接进入统一登录恢复；刷新后的项目初始化请求等待登录完成再继续，定时数据请求保持暂停。编辑器数据尚未加载时不生成空白草稿覆盖现有备份。

验证环境：Windows，本机 Docker 已部署制品，独立 Chrome 无头浏览器，所有 /api 请求由测试拦截并模拟，无真实账号、凭据或业务写入。

- `node tools/test-session-recovery.cjs`：通过，并发恢复、身份核验、来源/窗口/nonce 拦截、请求暂停、单次 GET 重试、写操作不重放。
- `node tools/test-startup-smoke.cjs <bundled-playwright-path>`：通过，模拟平台新开窗口、真实 postMessage 交接、编辑器挂载、桥接参数清理、过期登录卡片显示、F5 刷新，无浏览器 pageerror。
- `docker compose up -d --build goview-designer`：重新构建部署，无数据库迁移。

未测：真实用户密码/验证码认证和生产业务数据恢复，不能将模拟接口结果当作真实认证闭环验收。设计器 build-cli 不含类型检查；独立类型检查的现有依赖版本兼容问题仍存在。

回滚：保留已工作的异步弹框加载与监听修正；若关闭登录恢复功能，仅回退本功能相关组件、会话恢复拦截和路由，不回退其他编辑器功能及用户未提交变更。
