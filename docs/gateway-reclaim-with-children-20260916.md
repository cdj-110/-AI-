# 超级管理员回收带子设备的网关

后台取消“存在子设备就拒绝回收”的限制，接口继续只允许 SUPER_ADMIN 使用。回收事务先解除下属子设备关联并标记 OFFLINE，再释放出厂档案绑定、删除云端网关设备。子设备 ID、编号、类型、租户、物模型和已有数据保持不变；不迁移至新租户、不批量删除。原云端网关的配置与事件仍按现有外键级联规则删除，前端确认提示已明确说明。操作日志新增解除关联的子设备数量，成功消息说明实际处理结果。

为允许多个已回收网关遗留同名子设备，新增迁移 `20260916180000_allow_detached_gateway_children`：根编号唯一索引不包含未关联的 GATEWAY_CHILD。设备创建的根编号查找与遥测/MQTT 状态接收同步排除未关联子设备，避免编号冲突和误更新旧档案。

验证：`npm run test:gateway-reclaim` 使用隔离模拟事务检查无子设备、12 个子设备、同名的其他网关子设备及已解除关联子设备、数据和原租户保留、失败回滚、未登记/未绑定拒绝及超级管理员角色限制。管理平台构建通过。此轮不操作真实网关回收，也未执行生产数据库迁移或部署；部署时须先备份数据库、执行迁移，并同步更新 API、ingest 和管理平台。
