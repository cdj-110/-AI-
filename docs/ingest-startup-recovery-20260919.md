# 云平台采集服务启动恢复

## 问题原因

云平台整体重启时，采集服务可能先于 TimescaleDB 就绪。原逻辑只执行一次时序数据库初始化；失败后该 Promise 永久处于失败状态。随后 MQTT 即使连接成功，连接回调也会直接返回，不再订阅任何上报主题，最终表现为 MQTT 客户端在线但订阅数为 0、EG100 在云平台离线。

## 修改

- TimescaleDB 初始化失败后按间隔持续重试，成功后再允许 MQTT 消息消费。
- MQTT 每次建立新连接后重新确认完整订阅集合。
- 任一订阅失败时自动重试全部订阅，已成功的重复订阅由 MQTT Broker 幂等处理。
- 连接代次发生变化时终止旧连接的重试任务，避免重复订阅任务堆积。
- 服务退出时中断待执行的重试等待，避免延迟退出。
- Compose 为 TimescaleDB 增加健康检查，采集服务优先等待数据库健康；应用层重试仍作为最终兜底。

## 验证
