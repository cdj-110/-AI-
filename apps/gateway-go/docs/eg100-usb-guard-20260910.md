## Program changes

- Persist optional history `storageUUID`; resolve the original filesystem even
  when mount directories change. A missing UUID does not fall back to another
  partition at the old path. Existing path-only config remains compatible.
- Runtime guard includes mount generation ID, UUID, device and read-only state;
  a lost generation stays invalid until the store is recreated.
- Lost storage blocks status database access and all `ensureDatabaseLocked`
  callers, including clear. No creation underneath an absent mount.
- Removable history connections use DELETE/FULL rollback journaling and disable
  data mmap. Local history keeps WAL. Normal removable operation no longer relies
  on the file-backed WAL shared-memory index implicated in the previous crash.
- Ordinary config saves preserve history writer/connection state. Actual history
  changes close the old writer before creating the new one.
- Legacy history forms preserve UUID binding; new storage selections bind UUID.

## Remaining limitations

- No physical pull/replug or power-fault injection on the live device.
- A lost runtime history connection pauses rather than silently reconnecting;
  after verifying the original volume, re-enable history or restart the service.
- Vendor management UI and automatic dialing are intentionally disabled. Do not
  simply re-enable them when adding 4G: first coordinate power ownership with the
  gateway and validate shared USB hub/power stability.
- FAT ESP was reported unclean; it is not the history volume. No mounted fsck was
  attempted. Offline filesystem repair requires its own safe maintenance window.
