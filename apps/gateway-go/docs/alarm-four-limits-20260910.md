# 告警上上限、上限、下限、下下限

已完成本地验证，并于 2026-09-10 17:15 部署 EG100；不修改现场规则。

## 配置

- 数值点位新增规则默认进入“四限告警”，上限默认勾选但不预填阈值，须填写后才能确定。
- 四项可单独启用、填写阈值和选择提示/警告/严重等级。默认上限、下限为警告，上上限、下下限为严重。
- 仅比较启用项，要求下下限 < 下限 < 上限 < 上上限。零和负数均支持；至少启用一项，空值、非有限数、相等和顺序错误均拒绝。
- 四限使用严格比较：上限/上上限为大于，下限/下下限为小于；等于阈值不触发。需要包含等号时可使用原有单阈值模式。
- 各限值独立触发和恢复，超过上上限时上限也会成立；因此可能同时存在两个高侧告警。低侧同理。
- 共用父规则的回差、触发延时、恢复延时、启用状态及允许手动恢复策略。各子告警独立计时、确认和手动恢复；手动恢复上限不会屏蔽随后发生的上上限告警。
- 原有单阈值规则保持比较方式、规则标识和阈值，不自动转换。布尔/质量规则不显示四限选项。

## 实现

- 保存配置仍是一条父规则，新增 `limits.lowLow/low/high/highHigh`，每项包含 `enabled`、`threshold`、`level`。
- 告警运行时展开为四条以内独立子规则，标识为 `<父规则ID>::<限值key>`；告警名称追加中文限值名称。校验展开标识冲突，避免与手动配置的规则重名。
- 告警历史、确认、恢复、SQLite 手动恢复状态持久化继续复用原有实现；不新增数据库表。
- 无关配置热加载不重复触发；修改/关闭某一限值仅结束相关运行时告警，保存配置保持父规则形式。
