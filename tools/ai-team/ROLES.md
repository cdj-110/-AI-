# V1 实际角色与权限

| 角色 | 输入与职责 | 输出与执行边界 |
|---|---|---|
| 规划 | 用户任务、最多 12 个指定上下文文件 | JSON 计划；只读 Codex 调用 |
| 开发 | 同一任务、上下文、计划 | JSON 文件候选，最多 8 个文件/150KB；控制程序校验后写入任务克隆 |
| QA | 真实文件和既定模块验证入口 | 文档检查或断网容器测试；失败立即结束任务 |
| AI 审查 | 原任务、计划、具体候选、验证结果 | JSON 审查；拒绝后不得进入发布状态 |
| 发布准备 | 成功任务的提交、文件摘要、当前远端 main | 再次校验后推送 ai/task-*；GitHub CI 全部成功才由机器人创建草稿 PR |
| 人工审批 | PR 最终差异、提交 SHA、真实 CI、未测范围 | cdj-110 本人审查与决定合并；AI 不代批 |

规划、开发和审查是本机同一 Codex 登录下的顺序角色，不是三个独立账号。QA 和发布准备由程序执行，不由模型自报通过。第一份真实文档任务的候选已纳入初始审核 PR；初始基线合并前，新任务不应向 main 发布。

V1 白名单仅覆盖任务文档和云前端/API/ingest 的 src 文件。知识基线、CI、主分支保护、数据库迁移、Go 网关/GoView、生产发布、设备写入、授权签发与收费变更均需单独授权与验收方案。不要将本表理解为对这些操作的授权。
